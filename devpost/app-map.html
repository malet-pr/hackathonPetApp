Pet Care: from a tap to a saved treatment

A local Android organizer for pet profiles, actual flea-treatment history, optional next dates, photos and phone reminders. Demo practices the same care loop with temporary records and one sample day per real minute.

Source snapshot: bf1d470. This guide can drift as the code changes.

After the transaction succeeds, the ViewModel reconciles reminders and returns to detail. Room emits the updated history; the screen observes it. Real mode uses a file-backed database and Android alarms. Demo uses in-memory Room, an accelerated clock and a foreground event pump. There is no server.

Three-stop reference route

All paths below are relative to the repository root. In Android Studio, search for the named symbol.

  1. app/src/main/java/com/example/petcare/ui/TreatmentScreens.kt — TreatmentForm: fields read ViewModel state; onValueChange callbacks update it. The Save button invokes saveConfirmation when confirming.
  2. app/src/main/java/com/example/petcare/ui/PetCareViewModel.kt — startConfirmation / saveConfirmation: today is the initial actual date, fields start blank, and a coroutine calls the repository. After saving, reminder cleanup runs and the screen returns to Detail.
  3. app/src/main/java/com/example/petcare/data/TreatmentRepository.kt — confirmTreatment: validates the chosen actual date and current plan revision. A Room transaction inserts a new Administration and marks the plan COMPLETED together. Previous medication history stays unchanged.
Kotlin connections for a Java reader

model::saveConfirmation is a function reference. by mutableStateOf(...) delegates state storage so Compose can observe changes. viewModelScope.launch starts lifecycle-scoped coroutine work; suspend functions can wait without blocking the UI thread. Room's transaction groups database changes atomically; Android alarm operations occur afterward and can require a retry.

repository.reminderLock.withLock acquires a coroutine Mutex shared by cooperating reminder operations in this process. Waiting suspends the coroutine; the mutex does not automatically protect every database access. database.withTransaction separately makes grouped database changes atomic.

To change this, start here

  • Form wording or layout: ui/TreatmentScreens.kt, TreatmentForm.
  • Welcome and navigation: ui/AppShell.kt, ui/SettingsSheet.kt, ui/HomeScreen.kt.
  • Earthy colors: ui/theme/Theme.kt.
  • Reminder times and postponement eligibility: reminders/ReminderRules.kt; Android scheduling and cancellation: reminders/AlarmScheduler.kt, reconcile.
  • Notification content/actions: reminders/NotificationHelper.kt; incoming navigation: MainActivity.kt, routeNotification.
  • Demo speed and starting samples: demo/AcceleratedClock.kt, RATIO, and demo/DemoSession.kt, create.
  • Persistence and photos: data/PetCareDatabase.kt, data/TreatmentRepository.kt, data/PhotoStore.kt. Settings use data/SettingsStore.kt.

These short paths are under app/src/main/java/com/example/petcare/. Pet deletion is deferred; a future design should address history and pending reminders together.

A practice to reuse

Write an observable example before implementing a state change: October medication A must remain in history when November medication B is confirmed with its selected administration date. The approved PRD's Administration Confirmation section led to separate administrations and plans; app/src/androidTest/java/com/example/petcare/TreatmentLifecycleTest.kt checks the lifecycle, and the learner verified changed-medication history in Demo.

For platform uncertainties, test the actual interaction. Demo's posted notifications were followed by real notification-body and action taps on the emulator. That distinguished navigation from expansion-arrow interaction and exposed the practical 20-second postponement window. Foreground Demo evidence does not prove background delivery; the real postponed-alarm check is recorded separately in devpost/build-step-3.md.

Run and reopen

Open the repository root in Android Studio, use its bundled JBR 25 as Gradle JDK, select the debug variant and app configuration, start an emulator, then Run. Java 17 is the bytecode target. Full instructions and verification commands are in README.md.

Open devpost/app-map.html in a browser whenever you need this guide. It works offline with scripts disabled. Automated device tests use the separate verification app so their cleanup preserves normal debug records.
